# R2 — independent Viewer and Query

R2 is accepted and merged at `31aaffacd28b5d8da21ab0aac2e84d3b50b0296a`.
Current shared presentation and navigation are documented in [R3](R3.md).

Baseline: accepted R1 merge `2e5842610187d55fffae64ff2cf7d4c6d8a816b4`.
R2 adds workflow separation only. R3 design systems, Studio changes, persistence,
production configuration and deployment are outside this implementation.

## Workflow and lifetime

- `/boq`: WBS tree, breadcrumbs, existing charts, read-only paginated rows.
  Viewer totals cover every accepted row in its WBS scope, not just the page.
- `/query`: searches every accepted row in the **selected sheet**, regardless
  of Viewer scope. It does not combine Project and detail sheets (double-counting).
- Upload once, or explicitly choose **Use synthetic demo**. Client-side links,
  browser back/forward and Home/Media/Report round trips retain the BOQ session.
  Each browser tab owns a separate in-memory session. No project bytes go to a
  server, browser storage or URL. Refresh/full document navigation clears it;
  the empty state tells the user to select a workbook again. Download Demo
  always downloads the synthetic sample, never the current private workbook.
- Query draft/applied text, Any/All, WBS/Unit filters, pending/applied exclusions,
  detail/summary, sort and pages persist between routes. Viewer scope/page are
  independent. Excluding a Query row never deletes it from Viewer/source data.

## Source changes and identity

The root client provider creates one Zustand store per mounted application,
not a server singleton. SheetJS reads the binary once per workbook selection.
Supported sheets use the R1 header discovery and filtering rules. Accepted
rows for a sheet are normalized on demand and cached for that workbook.

IDs combine workbook generation, sheet name and original accepted-row index,
assigned before searching/filtering. Equal-looking duplicate rows have distinct
IDs; switching search or returning to a cached sheet does not reindex them.
Successful replacement creates a new generation. These are session identities,
not persistent business keys or physical Excel row numbers.

A successful file/sheet change resets Viewer and Query together. Invalid input
keeps the previous source, sheet and work with a named, actionable error. During
loading, rows/actions are paused; another upload/demo can supersede the request.
Only the latest asynchronous read/parse can commit data or errors. Sheet changes
are disabled during loading. Deferred PDF work checks the source revision before
saving, so it cannot download a replaced workbook's result.

## Preserved contracts

R1 BOQ positive Amount / usable Description exclusions remain unchanged,
including Excel Description error cells. Any/All literal Thai/English search,
OR within a filter / AND across filters, Description+Unit grouping, stored
Amount arithmetic, 20-row pagination, staged exclusions and CSV/PDF remain.
CSV exports all matched rows with existing formula-text escaping. PDF caps at
2,000 exported rows (detail rows or summary groups); CSV has no new row cap.
Summary totals cover all matched groups, not only the visible page.
Blank WBS values are selectable through the tree; charts retain their existing
omission of blank labels. Viewer rows/totals still include those records.

Public and authenticated modes use the existing server guards; `/query` is
inside the protected workspace layout. Public mode requires no Supabase.
Admin/API restrictions, authenticated rollback, Report input/cached-formula
requirements and synthetic-only public examples remain as documented in R1.
There are no runtime dependency or lockfile changes. Production audit still
reports 27 entries (0 critical, 4 high, 17 moderate, 6 low); R1 exposure decisions
remain applicable because the dependency use and privileged paths are unchanged.

## Reproduce verification

Use Node 24.19.0 and pnpm 11.25.0 (the verified versions), with no secret
`.env.local` file. pnpm 11 requires Node 22.13 or newer. Commands assume a POSIX shell.

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm lint
OKD_ACCESS_MODE=public NEXT_TELEMETRY_DISABLED=1 pnpm build
pnpm exec playwright install chromium
pnpm test:browser
pnpm audit --prod --json
```

`TEST_CHROMIUM_PATH=/absolute/path/to/chromium pnpm test:browser` can use an
installed Chromium. Browser scripts start/stop their own local production
servers (ports 3187 and 3190). They block outside network and use synthetic
fixtures created in memory. Existing R1 script also supports private reference
paths through `PRIVATE_BOQ_FILE`, `PRIVATE_BOQ_ROWS`, `PRIVATE_PROGRESS_FILE`;
never distribute those inputs or private exports.

```sh
OKD_ACCESS_MODE=authenticated NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:43999 NEXT_PUBLIC_SUPABASE_ANON_KEY=synthetic-test-anon pnpm build
node tests/auth-smoke.cjs
OKD_ACCESS_MODE=public NEXT_TELEMETRY_DISABLED=1 pnpm build
```

The final public rebuild must run without Supabase variables. Test logs and
actual counts accompany the R2 delivery report. Unit tests exercise actual
session transitions, parser and races; browser tests exercise route state,
exports, malformed input and the public security surface.

## Limits

No native Windows/macOS/Excel, physical phone, live account/RLS, deployment or
external media-playback acceptance is claimed. Headless checks use desktop and
390px mobile viewports. Very large/hostile workbooks can still consume browser
CPU/memory; parsing is not worker-isolated or decompressed-byte bounded. Existing
R1 dependency deferrals and their monitoring conditions remain. Workbook state
is deliberately ephemeral, not recoverable after refresh. No new PO product
decision is required by R2.
