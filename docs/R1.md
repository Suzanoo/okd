## Modes and rollback

Set server-only `OKD_ACCESS_MODE=public` for anonymous Home, BOQ/Query, Report
and Media. Public navigation has no Login/Logout/Admin actions. Middleware and
private entry points deny `/admin`, `/api/admin/*`, `/login` and `/logout` before
auth work. Public pages need no Supabase configuration or session refresh.
Do not use a client-side mode switch or `NEXT_PUBLIC_` access-mode variable.

Missing mode defaults to `authenticated`. Only exact `public` and
`authenticated` are valid; other values fail closed. To roll back, set
`authenticated`, restore the existing Supabase environment, rebuild and restart.
Keep the synthetic public samples. Auth guards and anonymous HTTP behavior are
tested; successful live login, production RLS and actual accounts were not tested.
Revalidate those against a disposable backend before enabling authenticated
production operation. Never expose service-role credentials to the browser.

## BOQ contract

Each supported sheet has its first nonblank row as headers: `WBS-1`, `WBS-2`,
`WBS-3`, `WBS-4`, `Description`, `Unit`, `Qty`, `Material`, `Labor`, `Amount`.
Extra columns are ignored. Select consolidated Project OR a detail sheet; do
not add both. Stored numeric Amount is used without recalculating from quantity
or rates. Commas in numeric text are accepted; invalid numeric cells become 0.
Blank quantity is 0 under the existing contract. Unit can be blank.

Keep only positive Amount and usable Description. Trimmed case-insensitive
placeholders blank, `0`, `-`, `--`, `n/a`, `na` are excluded. Excel Description
error cells are blank in the reader and excluded, even with positive Amount.
This is accepted filtering, not a parser defect or financial reconciliation
promise for excluded rows. The four known #REF! rows in the original reference
are expected exclusions. Filtering semantics are unchanged.

Query uses case-insensitive literal partial Description matching. Any matches
at least one word; All requires every word. Summary groups Description + Unit;
detail retains WBS. Exports use the accepted/filter-matched rows, including
rows outside the displayed page. CSV uses UTF-8 BOM and CRLF. Text starting with
formula trigger characters (including after whitespace) is prefixed with an
apostrophe to prevent Excel formula execution; numeric cells remain numeric.
This affects CSV text serialization only, not filtering or arithmetic. PDF
uses the existing Thai font and table output. Mixed-unit Qty totals are not a
physical quantity and should not be used as one.

## Progress Studio input contract

Required named sheets remain `progress` and `progress_table`; hidden sheets are
supported. No Studio format changes or extra sheets are required.

`progress` requires unique headers `project_start`, `project_finish`,
`week_start`, `plan`, `actual`. Project dates are valid and consistent across
rows; finish is not before start. Weeks are valid, unique and sorted on import.
Plan and Actual are cumulative project percentages on scale 0–100. Plan must
exist. Blank Actual means unavailable, never zero. Actual zero is valid. No
inference from main or other sheets replaces missing values. Monthly view uses
the latest weekly observation in each month, never a sum of cumulative values.
Actual chart values stop at the selected cutoff; nulls remain gaps.

`progress_table` requires unique `WBS`, `Activities`, `Amount`, `P/A`,
`%Progress` headers and weekly date columns. Optional `_Kind` is metadata:
project, wbs or activity. Without it legacy rows are activities. Unknown
nondate columns are rejected. Each kind/WBS/Activities identity must have one
P and one A row, with equal nonnegative Amount. Ambiguous duplicate identities
are rejected instead of silently merging. Source order and hierarchy are kept;
zero-weight milestones/rollups remain visible. Parent totals are never added
to child totals. The UI labels each row kind.

Weekly table cells are incremental percentages; sum through the cutoff to get
cumulative progress. Blank cells mean unavailable; an incomplete prefix has no
invented total. `%Progress` is retained as source metadata, not substituted for
selected-cutoff progress. Percent values and running totals must stay within
0–100 (0.0001 percentage-point rounding tolerance). Values above that are
invalid. Completed Amount/weight = source Amount * cumulative percent / 100.

Dates use raw Excel serials (1900/1904 workbook epochs), strict YYYY-MM-DD or
DD/MM/YYYY text. No local-time conversion is used; chart labels are UTC-stable.
Metadata cannot become a date. A serial's fractional time component is ignored.

Info is optional. When existing `Amount Initialization Source` is
`manual_placeholder`, label values `Weight (placeholder)`. Otherwise label
`Amount / weight (source units)`; OKD does not certify these as contract money
or infer a currency. No monetary source is reconstructed from other sheets.

### Formula values and recovery

OKD reads saved Excel results and does not calculate formulas. Required sheets
with formula cells lacking saved results or containing Excel errors are
rejected with sheet/cell and recovery instructions. Missing schema, malformed
numbers/dates, bad pairs and oversized reports are also actionable errors.
The previously loaded workbook stays visible and is explicitly named in the
failure message. A late demo response cannot overwrite an upload; a later
upload supersedes an earlier one. Choosing the same file again works.

For an uncalculated Studio workbook:

1. Open a copy in desktop Excel. Set Formulas > Calculation Options > Automatic.
2. Use Formulas > Calculate Now. On Windows Ctrl+Alt+F9 forces full calculation;
   on Mac use the calculation controls available in that Excel version.
3. Save as .xlsx, close and reopen. Confirm the intended export sheets have
   calculated dates and percentages, then upload that saved copy.
4. If activity data changed, first use Studio's existing Rebuild/Export to
   refresh the snapshot, then recalculate and save the resulting workbook.

No native Excel run was available in engineering. Synthetic formula-cache
fixtures verify both populated caches and missing-cache rejection. The supplied
uncalculated real Progress input was correctly rejected; its values were not
fabricated to manufacture a successful real-project report. Its actual
post-Excel reporting values remain unverified.

### Live and snapshot

The chart/KPI uses saved `progress` live-formula results. The table uses the
`progress_table` snapshot. Excel recalculation alone does not rebuild snapshots.
Dates must align. When a project pair exists, cumulative snapshot project values
are compared with available live values (0.01 percentage-point tolerance).
A mismatch withholds the table and requests Rebuild/Export while retaining valid
live chart data. A persistent notice explains the distinction. Agreement cannot
certify every activity's freshness; there is no reliable snapshot revision
marker, and no new Studio metadata is invented.

KPI variance is Actual minus Plan. The duration proxy is variance times planned
duration, explicitly labeled as a proxy, not critical-path schedule delay.
Unavailable Actual suppresses comparison KPI; available Plan is stated separately.

## Scope, privacy and limits

Public examples are the two synthetic workbooks only: BOQ 25 rows / 32,500 total;
Progress six weeks / two P/A activity pairs, final Plan 100 / Actual 95.
Download Demo always downloads the demo, including after an upload. Private
reference workbooks are not included in public assets or delivery packages.
Old repository history, deployments and copies are not retracted by replacing
current samples; the owner must manage those separately if still published.

Uploads are browser-local and not persisted. In R2, BOQ survives client route
navigation in the same tab; refresh clears it with a re-selection message.
The BOQ demo is explicit. Report retains its R1 demo-on-mount behavior.
Report has a 20 MiB compressed input limit and a postparse bound of 20,000
body rows / 521 columns per required sheet. These are practical limits, not a
proof against arbitrary compressed archive resource exhaustion. Large or
hostile local files can still consume browser memory/CPU; no remote upload/parser
endpoint exists. Use expected Studio workbooks. General workbook compatibility,
worker isolation and hard decompressed-byte limits are future work.
YouTube media playback needs external network and was not exercised end-to-end.
390px headless checks are not physical-phone acceptance. Native OS/Excel and
deployed CDN behavior have not been certified.

## Security decisions, 19 October 2026

Targeted fixes: Next 16.1.6 -> 16.3.8 (including resolved sharp 0.35.5),
matching eslint-config-next 16.3.8; SheetJS npm 0.18.5 -> official CDN 0.20.3;
jsPDF 4.1.0 -> 4.2.1. No broad package modernization. Lockfile pins transitives.
Next public framework/image processing and arbitrary local XLSX reading justify
immediate patching; PDF patch is a small compatible hardening change. Sources:
Next security advisories GHSA-2xp9-vwfh-vxw4, GHSA-cjq9-62q9-8jv4;
SheetJS CVE-2023-30533 and CVE-2024-22363; jsPDF GHSA-wfv2-pwc8-crg5.
SheetJS's official CDN is required because npm's latest xlsx remains obsolete.

Production audit: 79 -> 27 advisories (0 critical, 4 high, 17 moderate, 6 low).
Full dependency/dev audit: 67 version-specific entries covering 55 distinct
advisory IDs (0 critical, 33 high, 28 moderate, 6 low entries).
These are audit counts, not counts of reachable exploits. Detailed advisory
IDs/versions/remediation and evidence are in the delivered security register.
No unresolved credibly reachable material critical risk was identified in the
public workflows after these fixes; this is not a penetration-test guarantee.

Deferred with conditions:

- DOMPurify 3.3.1 is optional jsPDF HTML support. Application exports use text,
  autoTable and save; no HTML rendering or raw HTML insertion path consumes
  workbook text. Review/patch before adding HTML-to-PDF.
- ws 8.19.0 belongs to Supabase realtime. Public mode constructs no Supabase
  client and no WebSocket server/channel exists in application code. Reassess
  before enabling realtime or live authenticated production rollback.
- fflate 0.8.2 malformed ZIP64 unzip path is not used by PDF text/table generation;
  XLSX uses SheetJS. Review before accepting archives through fflate.
- Babel, browserslist, baseline-browser-mapping, source-map-js and dev-only
  lint/CSS/glob dependencies process trusted source/build configuration, not
  uploaded workbooks or public query parameters. Do not expose development
  servers or build arbitrary untrusted projects with this toolchain.

Monitor upstream advisories before release and after any new feature opens one
of these paths. A newly reachable material finding needs renewed triage.
Deferred risk acceptance belongs to PO; engineering recommends the documented
deferrals for this public release candidate.

## Reproducible engineering verification

Use a clean copy with no real credentials in .env files. No Git/deploy needed.

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm lint
pnpm exec playwright install chromium
```

POSIX: `OKD_ACCESS_MODE=public pnpm build`, then `pnpm test:browser`.
PowerShell: `$env:OKD_ACCESS_MODE='public'`, then `pnpm build` and
`pnpm test:browser`. Browser suite starts its own server, strips Supabase
environment, blocks external resources and checks public routes/refresh,
Admin/API denial, uploads, synthetic CSV/PDF, Report and 390px navigation.
Optional TEST_CHROMIUM_PATH selects an installed Chromium.

`node tests/report-contract.cjs` covers Studio-shaped synthetic inputs and
failure paths. Run in UTC, Asia/Bangkok and America/Los_Angeles for date proof.
Optional REPORT_FIXTURE_OUTPUT writes a synthetic test workbook; setting the
same variable for browser tests exercises its hierarchy and weights in the UI.

reference. Optional PRIVATE_BOQ_FILE / PRIVATE_BOQ_ROWS enable real BOQ browser
proof (1086 original; 1090 corrected). These files must remain outside the repo.
